# 寫一組能從頭做到尾的專案課程

1. 先讀 `AGENTS.md`、`src/data/projects.json`、`src/config/series.ts` 與該組所有 `seriesOrder`。從公開原始碼找實際入口、套件指令、服務與部署目標。若程式未公開，建立可獨立執行的練習並標示與正式產品的差異。
2. 排課時先寫下各篇「開始時手上有什麼 → 動手做什麼 → 結束時多了什麼」。首篇帶讀者看問題、成品、架構分工與所需環境。尾篇拿前面做過的功能走一輪驗收，以結果說明已涵蓋和未涵蓋的範圍。
3. 每個中間章節選一項可以建成的功能或串接。交代相對路徑、要新增或修改的位置、可執行的程式或精確設定。若是修改既有專案，要能從指定 revision 重現；若承接上篇，給連結與起始檢查。用一組具體輸入與輸出驗收，寫出最可能遇到的故障與檢查位置。
4. 在有介面的步驟，把真實操作圖放在相關設定或結果旁邊。圖說標明圖的來源、要看哪個按鈕或欄位、讀者該看到什麼。多個點擊可以共用一張圖，前提是都看得見；畫面與文字說明不同操作時必須換圖。程式與架構可改用短程式碼、可複製指令和資料流說明。正式產品畫面與獨立範例的執行結果分開標示。
5. 碰到 Vercel、Neon、Supabase 或 GitHub Actions，先讀 [部署截圖與驗收](references/deployment.md)。使用該專案實際的 framework、root directory、變數名稱、migration 和環境。已存在的圖用原路徑引用；畫面改版時先核對官方文件，新增或更新對應圖並留下來源。
6. 驗收時只開本章和文中提供的連結。在乾淨資料夾或測試帳號從頭操作，記下實際輸入、輸出和對應 commit。圈出只有作者本機才有的檔案、未填的變數、無從取得的前一步輸出，修正後重跑。模型圖與產品畫面只能驗證圖上看得到的事。把本機、CI、官方示例及仍需登入才能測試的範圍寫清楚。
7. 檢查每張圖、部署後的 base path、上一章／下一章及系列卡片預覽，執行 `npm run check:taxonomy`、`npm run build` 和 `npm run check:seo`。最後逐篇回答「讀者關掉公開產品、改用自己的工作目錄或測試帳號，這一章完成後多了什麼？」若只能回答「看過設定、點過按鈕」，就補上實作或串接，並重新驗收。
